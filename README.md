# 自动收获

适用于《我的世界》（Minecraft）的自动收割模组。

> ⚠️ **注意**：由于精力有限，新功能与内容仅在**最新版本**中加入；旧版本仅进行 Bug 修复，不再添加新特性。

## 用法

- 按下 **`H`** 键开启或关闭模组功能。
- 默认启用 **种植模式**。

## 模式说明


| 模式         | 指令                         | 功能描述                                               |
|--------------|------------------------------|--------------------------------------------------------|
| **种植模式** | `/autoharvest mode plant`    | 自动种植手中的农作物（如小麦种子、胡萝卜等）到空耕地。 |
| **收割模式** | `/autoharvest mode harvest`  | 自动收割已成熟的农作物。                               |
| **除草模式** | `/autoharvest mode weed`     | 自动清理耕地上的杂草（如草、高草等）。                 |
| **喂食模式** | `/autoharvest mode feed`     | 自动对可繁殖动物使用食物，触发繁殖行为。               |
| **锄地模式** | `/autoharvest mode hoe`      | 自动将水源附近的草方块或泥土变为耕地。                 |
| **钓鱼模式** | `/autoharvest mode fishing`  | 自动投掷鱼竿并收杆，实现全自动钓鱼。                   |
| **催熟模式** | `/autoharvest mode bonemeal` | 自动对未成熟的农作物使用骨粉进行催熟。                 |
| **农夫模式** | `/autoharvest mode farmer`   | 结合收割与种植：自动收割成熟作物并立即重新种植。       |

> 💡 **提示**：切换模式后，模组将会自动变为 **开启状态**（按 `H` 切换开启或关闭状态）

## 26.2 分支配置

- **使用玩家交互距离 `rangeSource`**：布尔开关，默认 `false`。`false` 使用配置文件中的 `radiusCenti`（10–65，表示 1–6.5 格）；`true` 实时读取玩家的 range 属性，方块交互使用 `blockInteractionRange()`，喂食/剪羊毛使用 `entityInteractionRange()`，包含装备、效果等属性修饰。启用时不额外套用自定义半径或隐藏上限；客户端无法绕过服务器规则。旧配置中的 `CUSTOM`/`PLAYER_ATTRIBUTE` 会自动转换为 `false`/`true`，保留已有半径和其他配置。
- **单 tick 最大操作数 `maxActionsPerTick`**：1–64，默认 1。`ticksPerAction` 仍控制两批操作的间隔，每个执行 tick 使用有界扫描处理多个不同目标。预算统计已发送的交互尝试，不保证服务器接受；农夫模式收割和补种共享预算（默认 1 时分不同 tick 完成）。补给/切换物品不计为世界交互。时运工具切换仍延迟到下一次执行，钓鱼状态机与收杆/抛竿间隔不加速。
- **交互时挥手 `swingHand`**：默认关闭。启用时遵循原版交互结果，以实际主手/副手调用原版挥手，其他玩家可正常看到。无重复自制动画包；无法屏蔽服务器自行触发的动画。喂食原有的无条件挥手也改为受此开关控制。

### 性能与验证

扫描去除了每格中心向量分配和重复的锄地扫描，水检测复用可变坐标与方块状态，并包含上游 a92220ec 的修复：检测同层和上一层的水。所有半径均保留扫描进度，避免最近的未变化目标反复占满预算；扫描末尾可在同一次调用内继续下一轮，不额外插入空闲 tick。大范围同时保留小范围的当前位置扫描和最多 256 个最近操作目标，缓解完整扫描外层空区域造成的动作间断。全范围扫描优先推进，局部扫描也轮转；目标每次使用前仍重新检查状态、位置和玩家当前交互距离，每次调用不重复操作同一扫描目标。这三部分合计最多检查 4,096 个位置（包括球外的原始立方体位置），不缩减配置范围。普通移动不重置全范围进度，大幅位移（超过扫描直径）、切换世界或修改范围后重置。保留目标不代表服务器已接受交互，服务器延迟、拒绝和原有操作间隔仍会影响实际动作。农夫补种队列有数量、重试与过期限制，避免长期积累。客户端出现幼苗后继续观察 40 tick，以便回滚为空气时重试，这只是有限的预测宽限期，不是服务器确认。未完成的补种最多保留 1,200 tick；512 项队列满时暂停新的需补种收割。

已合入本 fork 的 `fix/flowing-water-26.2` 修复（`fac8a315`、`a004328`）：锄地识别同层/上一层、水平 4 格内的静水和流水；甘蔗相邻检查使用原版支持标签，包含流水、含水方块及默认标签中的霜冰（不包含普通冰）。水变化每次扫描时重新检查，保留可变坐标和方块状态复用优化。

可运行以下独立回归检查（Python 3、JDK 21+），不调用 Gradle：

```bash
python scripts/test_scans.py
python scripts/test_interactions.py
python scripts/test_water.py
```

扫描检查使用按曼哈顿距离遍历、复用可变坐标的替身，覆盖小范围公平性、大范围连续操作、移动中发现目标、循环边界、多操作去重及扫描工作量上限。交互检查也验证传给原版的目标坐标不会随扫描游标改变。

配置迁移检查另需现有的 Gson JAR：`python scripts/test_config.py /path/to/gson.jar`。它使用真实 Gson 检查旧枚举到布尔值的迁移、保存/重读、其他配置保留，以及切换后的方块/实体距离来源。

这些检查使用最小 API 替身验证工具逻辑，不代表真实 Minecraft API 编译或游戏内测试。遵循 `AGENTS.md`，本次未运行任何 Gradle 构建/编译；Fabric 与 NeoForge 构建及客户端/多人服验证仍需手动完成。建议先以 1 次操作测试，再逐步提高预算，并遵守服务器规定。
